DubStubs Security Audit

Audit date: 2026-05-14. Branch: security/dubstubs-audit. Target: _codexV1.

A. Executive Summary

The duplicated app is a static ticket designer with one PHP Replicate proxy. No database, payment flow, admin area, or server-side upload storage was found. The serious launch risk is the cost-bearing AI generation route.

Architecture And Attack Surface

DubStubs uses index.html, styles.css, browser localStorage, client-side file reads, client-side PNG export, and one PHP/cURL API route that calls Replicate.

Generation Tracking

The PHP route now writes safe JSONL events to /home/YOUR_CPANEL_USER/private/dubstubs-logs/generate-events.jsonl. It records request ID, IP hash, prompt length/hash, Replicate HTTP status/id, generated image host, content type, and byte size. It does not log raw prompts, API tokens, full provider responses, or image bytes.

C. Quick Wins

  • Confirm the private rate-limit and log directories are writable on cPanel.
  • Escape f.role and reduce innerHTML use.
  • Set Replicate spend alerts and monthly caps outside code.

D. Must-Fix Before Public Launch

  • Decide whether public generation also needs Basic Auth, Turnstile, or invite-code gating.
  • Confirm the cPanel private directory is outside public_html and writable by PHP.
  • Set Replicate spend alerts and review generation logs during beta.

E. Suggested Pull Requests

  1. Secrets and env cleanup: implemented in this branch.
  2. API hardening: basic rate limit, 429 shape, generated-image URL checks implemented.
  3. Input validation: upload limits and filename slugging implemented; numeric clamps still worth tightening later.
  4. Upload/generated file safety: keep browser-only storage or write outside webroot.
  5. Production headers and logging: confirm .htaccess, add CSP after inline JS is moved, add HSTS after HTTPS verification.
